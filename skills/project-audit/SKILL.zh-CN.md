# 项目体检

新项目接手，或产品变化已经让旧增长假设可能失效时使用。体检阶段以只读为主，不在诊断过程中直接修改生产环境。

## 检查

1. 仓库、README/Docs、架构、部署配置、公开页面、定价、注册/Onboarding、核心流程和可访问的支付路径。
2. 现有产品事实、自主权策略、实验、工作日志、分析数据、搜索数据、客户反馈、Issue/支持和历史 Campaign。
3. 当前获客 -> 注册 -> 激活 -> 付款 -> 留存路径，包括未测步骤和定义不一致。
4. 营销声明与代码实现、公开证据之间是否一致。
5. 当前可执行能力：代码/部署、分析、搜索、支付、发布、浏览器、内容，以及每种能力的权限范围。

## 分类

每个发现记录：观察事实、证据/来源、用户/业务影响、置信度、可能使用的角色/Skill、成本、可回滚性，以及是否阻碍可信测量。

在扩大获客前优先修复测量阻塞和严重产品/漏斗问题。不能把“没有数据”误判成“表现差”。

## 交付

给出简明产品模型、漏斗图、测量图、权限图、已验证卖点、未知信息、主要约束/假设和最小安全下一步，并交给 `growth-strategy` 做约束判断。
