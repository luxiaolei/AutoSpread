# Search Experience Optimization

Use when a technically healthy page still underperforms, when the ranking page type appears wrong for a query, or when search traffic lands but does not progress.

## Method

1. Define the target query/topic, audience, intended page, and downstream action.
2. Observe the current search surface using an appropriate source. Record dominant result types and formats rather than relying on remembered SERP patterns.
3. Classify the target page and relevant results using the same taxonomy: product, category, comparison, tool, landing page, guide, list, local page, video, forum/community, documentation, or another explicit type.
4. Identify strong consensus, mixed intent, or fragmented results. Treat SERP consensus as evidence about intent, not a command to clone competitors.
5. Derive user needs from query wording, related questions/searches, result formats, ads/commercial signals when observable, customer evidence, and the page's actual funnel role.
6. Compare the page on: intent/page-type fit, answer/findability, above-fold clarity, trust/proof, media/tool usefulness, internal next step, and mobile usability.
7. If the page attracts search visits but downstream quality is weak, combine this with product analytics/CRO before changing content merely to rank better.

## Output

Return the observed search pattern, target-page classification, mismatch or opportunity, user stories/questions, concrete structural/content changes, downstream CTA/destination, and a verification experiment.

Do not use arbitrary word-count targets as a ranking rule. Do not assume the current SERP is permanent; record date, locale/device when material, and source limitations.
